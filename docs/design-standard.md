# 設計標準

## 必須事項

- システム境界、利用者、外部依存、信頼境界を図または文章で示す。
- コンポーネントの責務、インターフェース、失敗時の動作を定める。
- データの収集、変換、保存、共有、削除までの流れを示す。
- 認証、認可、監査、暗号化、秘密情報管理を設計する。
- タイムアウト、再試行、冪等性、縮退、復旧、ロールバックを検討する。
- 主要な代替案と採否の理由を記録する。

## AI機能の追加設計

モデルやサービスの責務を限定し、入力制御、出力検証、根拠表示、人的介入、評価データ、モデル変更時の再評価を設計します。確率的出力を通常の決定ロジックと同じ前提で扱ってはいけません。

## 設計レビュー

実装開始前に、要求との対応、障害モード、セキュリティ、運用性を確認します。重大な未決事項は責任者と期限を付けて管理します。

成果物には [設計テンプレート](../templates/design-template.md) を使用できます。
