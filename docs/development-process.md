# 開発プロセス

## 工程と完了条件

| 工程 | 主な成果物 | 完了条件 |
|---|---|---|
| 企画 | 目的、対象、成功指標、リスク | 責任者と実施可否が明確 |
| 要件定義 | 要求、受入条件、制約 | 曖昧語が解消され追跡可能 |
| 設計 | 構成、データ、脅威、復旧方法 | 主要な代替案と判断根拠を記録 |
| 実装 | コード、設定、依存関係 | 検査と自己レビューが完了 |
| 検証 | テスト結果、残存リスク | 受入条件を満たし重大欠陥なし |
| リリース | 承認、手順、ロールバック | 実行者と監視方法が明確 |
| 運用・改善 | 指標、障害記録、改善項目 | 定期見直しと責任者を設定（[運用標準](operations-standard.md)） |

- **DEV-01（必須）** 各工程で、上表の主な成果物を作成し、完了条件を満たしたことを確認する。

## 追跡性

- **DEV-02（必須）** 要求に一意な識別子を付け、設計判断、実装変更、テスト、リリース記録へ関連付ける。
- **DEV-03（必須）** 重要な判断は、アーキテクチャ決定記録（Architecture Decision Record、ADR）として [ADRテンプレート](../templates/adr-template.md) で記録する。

要件から設計、実装、テスト、リリースまでの対応は [追跡表テンプレート](../templates/traceability-matrix-template.md) で記録できます。

## 変更管理

- **DEV-04（必須）** スコープ、リスク、データ利用、外部公開条件が変わる場合は、影響分析と再承認を行う。
- **DEV-05（必須）** 緊急変更でも、事後レビューと記録を省略しない。

## 例外管理

- **DEV-06（必須）** 例外は、[導入ガイドの例外](../ADOPTION.md#例外)に定める ADP-05 と ADP-06 に従って記録し、管理する。
