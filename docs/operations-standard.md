# 運用標準

リリース後のシステムを監視し、障害に対応し、改善するための規則を定めます。開発プロセスの「運用・改善」工程に適用します。

## 監視

- **OPS-01（推奨）** 利用者への影響を表す主要指標（可用性、遅延、エラー率など）と、警告の閾値を定める。
- **OPS-02（推奨）** 警告ごとに、受け取る担当者と初動の手順を定める。
- **OPS-03（必須）** ログと指標に、秘密情報や不要な個人情報を含めない（COD-04）。

## インシデント対応

- **OPS-04（推奨）** インシデントの[重大度](risk-and-roles.md#指摘の重大度)に応じて、連絡先、連絡までの時間、エスカレーション先を定める。
- **OPS-05（推奨）** インシデントの収束後に振り返りを行い、原因、影響、再発防止策を記録する（SEC-06）。
- **OPS-06（推奨）** 振り返りで見つかった標準の不足は、本標準の改善提案として報告する。

## AI機能の運用

- **OPS-07（推奨）** AI機能の出力品質を継続して監視する。評価セットの定期実行、利用者からの報告、品質指標の推移を確認する（TST-09、AIU-14）。
- **OPS-08（推奨）** AI機能の費用、利用量、遅延を監視し、上限と超過時の対応を定める。
- **OPS-09（必須）** 利用するモデルは、版を特定できる識別子で固定し、自動で更新される別名に依存しない。
- **OPS-10（推奨）** モデル提供元の版の変更や提供終了の予定を把握し、移行前に評価セットで再評価する（TST-09）。
- **OPS-11（必須）** AIによる有害な出力、データの流出、意図しない操作は、インシデントとして扱う。
- **OPS-12（必須）** AI機能を停止または縮退する手順を用意し、定期的に実行できることを確認する（AIU-14）。

## 保守と見直し

- **OPS-13（推奨）** 依存関係、証明書、秘密情報の更新を、周期を決めて実施する（SEC-02、SEC-04）。
- **OPS-14（推奨）** 運用の指標、障害記録、改善項目を見直す周期と責任者を定める。
