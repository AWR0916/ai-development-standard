# バージョニング方針

## 形式

標準のバージョンには、セマンティックバージョニング（Semantic Versioning、SemVer）の `MAJOR.MINOR.PATCH` 形式を使用します。Gitタグは先頭に `v` を付けます。

例：ファイルには `1.2.3`、Gitタグには `v1.2.3` を記録します。

## 変更区分

- `MAJOR`：既存プロジェクトの対応が必要となる必須規則の変更または削除
- `MINOR`：後方互換性を保った規則、テンプレート、検査項目の追加
- `PATCH`：意味を変えない訂正、説明改善、リンク修正

変更区分に迷う場合は、利用者への影響が大きい区分を選びます。

## リリース手順

1. 変更の影響と移行方法を確認する。
2. `VERSION` と `CHANGELOG.md` を更新する。
3. 関連する文書、テンプレート、チェックリストを更新する。
4. 文書検査を成功させる。
5. レビュー済みコミットへ `vX.Y.Z` 形式の注釈付きタグを作成する。
6. コミットとタグを公開する。

## 採用側の責任

各プロジェクトは採用バージョンを明記し、バージョン更新時に変更履歴と影響を確認します。既定ブランチを固定バージョンの代わりに参照してはいけません。
