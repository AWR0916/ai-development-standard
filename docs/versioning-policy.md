# バージョニング方針

## 形式

- **VER-01（必須）** 標準のバージョンには、セマンティックバージョニング（Semantic Versioning、SemVer）の `MAJOR.MINOR.PATCH` 形式を使用し、Gitタグには先頭に `v` を付ける。

例：ファイルには `1.2.3`、Gitタグには `v1.2.3` を記録します。

## 変更区分

- **VER-02（必須）** 変更は、次の区分に従ってバージョンを上げる。
  - `MAJOR`：既存プロジェクトの対応が必要となる変更。必須規則の追加、変更、削除と、推奨規則から必須規則への変更を含む。
  - `MINOR`：後方互換性を保った追加。推奨規則、テンプレート、検査項目の追加を含む。
  - `PATCH`：規則の意味を変えない訂正、説明改善、リンク修正、規則IDの付与。
- **VER-03（必須）** 変更区分に迷う場合は、利用者への影響が大きい区分を選ぶ。

## 規則ID

- **VER-04（必須）** 検証可能な規則には、`接頭辞-連番（必須）` または `接頭辞-連番（推奨）` の形式で、規則IDと適用レベルを付ける。
- **VER-05（必須）** 規則IDは、規則を削除した後も再利用しない。
- **VER-06（必須）** 規則の削除や統合では、`CHANGELOG.md` に旧規則IDと移行先を記録する。

接頭辞は次のとおりです。

| 接頭辞 | 文書 |
|---|---|
| DEV | [開発プロセス](development-process.md) |
| RQM | [要件定義標準](requirements-standard.md) |
| DSN | [設計標準](design-standard.md) |
| COD | [コーディング標準](coding-standard.md) |
| TST | [テスト標準](testing-standard.md) |
| SEC | [セキュリティ標準](security-standard.md) |
| AIU | [AI利用標準](ai-usage-standard.md) |
| REV | [レビュー標準](review-standard.md) |
| REL | [リリース標準](release-standard.md) |
| OPS | [運用標準](operations-standard.md) |
| RSK | [リスク区分と役割](risk-and-roles.md) のリスク区分と重大度 |
| ROL | [リスク区分と役割](risk-and-roles.md) の役割 |
| VER | バージョニング方針（本文書） |
| ADP | [導入ガイド](../ADOPTION.md) |

## リリース手順

- **VER-07（必須）** 標準のリリースは、次の手順で行う。
  1. 変更の影響と移行方法を確認する。
  2. `VERSION` と `CHANGELOG.md` を更新する。
  3. 関連する文書、テンプレート、チェックリストを更新する。
  4. 文書検査を成功させる。
  5. レビュー済みコミットへ `vX.Y.Z` 形式の注釈付きタグを作成する。
  6. コミットとタグを公開する。

## 採用側の責任

- **VER-08（必須）** 各プロジェクトは、採用バージョンを明記する。
- **VER-09（必須）** 採用バージョンの更新時に、変更履歴と影響を確認する。
- **VER-10（必須）** 既定ブランチを、固定バージョンの代わりに参照しない。
