# リスク区分と役割

この文書は、変更のリスク区分、指摘の重大度、開発で担う役割を定義します。他の標準にある「高リスク変更」「重大な指摘」「承認者」などは、この文書の定義に従います。

## 変更のリスク区分

変更は、次のいずれかの区分に判定します。複数の条件に当てはまる場合は、最も高い区分とします。

| 区分 | 判定条件（いずれかに該当） |
|---|---|
| 高 | 認証、認可、暗号、秘密情報の扱いを変更する |
| 高 | 個人情報、顧客データ、機密データの収集、保存、共有、削除の方法を変更する |
| 高 | 本番データの移行や削除など、元に戻せない操作を含む |
| 高 | 外部へ公開する機能、API、データ送信先を追加または拡大する |
| 高 | AIに書込み、送信、公開、削除、課金、権限変更の権限を与える、または広げる |
| 高 | 安全性、法令、契約上の義務に関わる機能を変更する |
| 中 | 利用者から見える機能や動作を変更する |
| 中 | AI機能のモデル、プロンプト、検索データ、評価セットを変更する |
| 中 | 依存関係をメジャーバージョンで更新する |
| 中 | 本番環境の設定や基盤を、元に戻せる形で変更する |
| 低 | 文書、コメント、テストだけを変更する |
| 低 | 利用者に影響しないリファクタリングや、開発環境だけの変更 |

- **RSK-01（推奨）** 変更ごとにリスク区分を判定し、Pull Request に記載する。
- **RSK-02（推奨）** リスク区分の判定に迷う場合は、高い方の区分とする。

### 区分ごとの統制

次の表は、区分ごとに求める統制の目安です。規則IDのある項目は、その規則に従います。

| 区分 | レビューと承認 | 検証 | リリース |
|---|---|---|---|
| 高 | 作成者以外で、対象領域の知識を持つ人が承認する（REV-04）。脅威分析を更新する（SEC-07） | 境界値、異常系、権限不足を確認する（TST-03）。ロールバックを検証する（TST-07） | 段階的公開を検討する（REL-06）。中止判断者を定める（REL-08） |
| 中 | 作成者以外の1名がレビューする（RSK-03） | 変更箇所の回帰テストを実施する | 公開後に主要指標を確認する（REL-07） |
| 低 | 自動検査と自己レビュー（REV-01、COD-09） | 必須検査の成功 | 通常の手順 |

- **RSK-03（推奨）** リスク区分が「中」の変更は、作成者以外の1名がレビューする。

## 指摘の重大度

レビュー、テスト、セキュリティ検査で見つかった問題は、次の重大度に分類します。

| 重大度 | 定義 | 対応 |
|---|---|---|
| 重大 | 悪用や発生により、データの漏えい・改ざん、人や財産への危害、広範なサービス停止を直接引き起こす | リリース前に解消する。できない場合は期限付きの例外とする（SEC-09、SEC-10） |
| 高 | 条件付きで重大と同等の影響を引き起こす、または限られた範囲で直接引き起こす | 重大と同じ |
| 中 | 影響が限定的、または他の防御で緩和される | 期限を決めて対応する（RSK-04） |
| 低 | 影響が軽微 | 記録し、改善時に対応する（RSK-04） |

REV-07 の「重大な指摘」と SEC-09 の「重大または高リスクの未対応事項」は、重大度が「重大」または「高」の指摘を指します。

- **RSK-04（推奨）** 重大度が「中」の指摘には対応期限を、「低」の指摘には記録先を定める。

## 役割

| 役割 | 責任 |
|---|---|
| 導入責任者 | 適用範囲、採用バージョン、プロジェクト固有規則、例外の台帳を管理する（ADOPTION.md） |
| プロダクト責任者 | 目的と要件を承認し、残存リスクを受け入れるかを判断する |
| 作成者 | 変更を作成し、自己レビューとAI生成物の検証を行う（REV-01、COD-08） |
| レビュアー | レビュー観点に沿って変更を確認する（REV-03） |
| 承認者 | 変更、例外、リリースを承認する（REV-04、REV-07、ADP-05） |
| リリース実施者 | リリース手順を実行し、公開後の確認を行う（REL-07） |
| 中止判断者 | 中止基準に基づき、リリースの中止や切り戻しを判断する（REL-08） |

- **ROL-01（推奨）** 導入時に、各役割の担当者を対象リポジトリに記録する。
- **ROL-02（推奨）** 一人が複数の役割を兼ねてもよい。ただし、承認者は自分が作成者である変更や、自分が申請した例外を承認しない。
- **ROL-03（推奨）** AIは役割を担わない。AIが作成した変更では、AIに作業を指示し、変更を提出した人を作成者とする。

### 工程と役割の対応

| 工程・活動 | 実施 | 承認 |
|---|---|---|
| 要件定義 | 作成者 | プロダクト責任者 |
| 設計 | 作成者 | 承認者 |
| 実装とPull Request | 作成者 | レビュアー、承認者 |
| 例外の申請 | 作成者または導入責任者 | 承認者 |
| 残存リスクの受け入れ | — | プロダクト責任者 |
| リリース | リリース実施者 | 承認者、中止判断者 |
| 採用バージョンの更新 | 導入責任者 | 承認者 |
