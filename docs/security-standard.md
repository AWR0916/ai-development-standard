# セキュリティ標準

## 必須統制

- **SEC-01（必須）** データと機能を分類し、最小権限でアクセスを制御する。
- **SEC-02（必須）** 秘密情報は承認済みの保管機構で管理し、定期的に更新する。
- **SEC-03（必須）** 通信中と保存中の保護要件を、データ分類に応じて定める。
- **SEC-04（必須）** 依存関係を固定・検査し、既知の脆弱性と供給網リスクを管理する。
- **SEC-05（必須）** セキュリティ上重要な操作を、改ざん耐性を考慮して監査記録へ残す。
- **SEC-06（必須）** インシデントの検知、連絡、封じ込め、復旧、振り返りを定める。

## 脅威分析

- **SEC-07（必須）** 設計時と重要変更時に、資産、攻撃者、入口、信頼境界、影響、対策、残存リスクを評価する。
- **SEC-08（必須）** AI機能の脅威分析には、プロンプトインジェクション、データ流出、過剰なツール権限、汚染データ、危険な自動実行を含める。

## 外部公開前

- **SEC-09（必須）** 外部公開前に [セキュリティチェックリスト](../checklists/security-checklist.md) を完了し、[重大度](risk-and-roles.md#指摘の重大度)が「重大」または「高」の未対応事項がないことを確認する。
- **SEC-10（必須）** セキュリティ上の例外は、期限付きで承認する。
