# レビュー標準

## 作成者の責任

- **REV-01（必須）** 提出前に変更差分を読み、目的外変更、秘密情報、生成物、デバッグ情報が含まれないことを確認する。
- **REV-02（必須）** 変更の説明に、目的、主な変更、検証結果、リスク、ロールバック方法を記載する。

## レビュー観点

- **REV-03（必須）** レビューでは、次の観点を確認する。
  - 要求と受入条件を満たしているか。
  - 設計と責務分担が一貫しているか。
  - セキュリティ、プライバシー、障害時動作に問題がないか。
  - テストが重要なリスクと境界条件を覆っているか。
  - 運用、監視、移行、ロールバックが実行可能か。
  - 文書、テンプレート、チェックリスト間に矛盾がないか。

## 独立性

- **REV-04（必須）** 高リスク変更（[リスク区分](risk-and-roles.md#変更のリスク区分)が「高」の変更）は、作成者以外の適切な知識を持つ人が承認する。
- **REV-05（必須）** AIによるレビューだけを、独立レビューとして扱わない。
- **REV-06（必須）** レビュー指摘を採用しない場合は、理由を記録する。

## 承認条件

- **REV-07（必須）** 承認前に、必須検査が成功し、重大な指摘（[重大度](risk-and-roles.md#指摘の重大度)が「重大」または「高」）が解消され、残存リスクと例外が承認済みであることを確認する。
