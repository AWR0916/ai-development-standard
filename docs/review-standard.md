# レビュー標準

## 作成者の責任

提出前に変更差分を読み、目的外変更、秘密情報、生成物、デバッグ情報が含まれないことを確認します。説明には目的、主な変更、検証結果、リスク、ロールバック方法を記載します。

## レビュー観点

- 要求と受入条件を満たしているか。
- 設計と責務分担が一貫しているか。
- セキュリティ、プライバシー、障害時動作に問題がないか。
- テストが重要なリスクと境界条件を覆っているか。
- 運用、監視、移行、ロールバックが実行可能か。
- 文書、テンプレート、チェックリスト間に矛盾がないか。

## 独立性

高リスク変更は、作成者以外の適切な知識を持つ人が承認します。AIのレビューだけを独立レビューとして扱いません。指摘を無視する場合は理由を記録します。

## 承認条件

必須検査が成功し、重大な指摘が解消され、残存リスクと例外が承認済みであることを確認します。
